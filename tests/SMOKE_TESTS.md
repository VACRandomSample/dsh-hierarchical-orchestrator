# SMOKE_TESTS — сценарии дымовых проверок иерархического оркестратора

Все проверки выполняются в изолированной песочнице `tests\sandbox\` (git-репозиторий) либо на read-only задачах. Отчёт с результатами: `docs\05-testing-report.md`, доказательства новой сессии: `tests\evidence\new-session-report.md`.

## S1. Глубина 0→1→2 (реальные активации)
Из корневой сессии: `subagent` (без preset) → ребёнок A; A: `subagent` → ребёнок B.
Проверка: получены оба child id; уведомления о завершении доставлены.

## S2. Отказ глубины 3
B (глубина 2) пытается запустить C.
Проверка: отказ runtime, потомок не создан.

## S3. Ёмкость пула 6
Параллельно 6 долгих детей; затем 7-й запуск.
Проверка: 7-й отклонён («active child limit: 6»); после завершения детей контрольный запуск успешен (слоты освобождены).

## S4. Роли через agent_preset
Новая корневая сессия: `subagent` c `agent_preset=ho-tech-lead` → тот делегирует `ho-explorer`.
Проверка: enum ролей в схеме инструмента; реальные id цепочки; отчёты ролей по форме.

## S5. Read-only enforcement
Explorer и Code Reviewer пытаются создать/изменить файл.
Проверка: пишущих инструментов нет в каталоге (NO-WRITE-TOOL-CONFIRMED).

## S6. Политика моделей
`list_subagent_models` в новой сессии; пробный ребёнок с явным маршрутом `zai/glm-5.3`.
Проверка: только маршруты политики; маршрут вне каталога/политики = явная ошибка без fallback.

## S7. Не зависит от внешнего шлюза
Политика и пресеты ссылаются только на `zai` (нативный pi-ai каталог). OmniRoute-провайдер не входит ни в один новый пресет/конфиг.
Проверка: grep бандла на `<external-gateway>|omniroute` = пусто; маршруты политики = `zai/*`.

## S8. Откат/восстановление
`remove_bundle` → `install_bundle` (репетиция).
Проверка: строки снимаются и возвращаются, warnings пуст, данные сессий сохраняются.
