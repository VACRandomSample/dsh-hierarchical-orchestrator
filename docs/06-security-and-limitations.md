# 06 — Безопасность и ограничения

## Инцидент 11–12.11: полный разбор (v1 → v2)

**Симптомы:** 11.11 ~23:00 и повторно 12.11 ~09:40 (после повторного включения): существующие сессии недоступны, отправка сообщений в текущую сессию не работает; запланированные тестовые сессии создавались, но агент в них не запускался.

**Действительная причина (уточнена 12.11 по исходникам):** бандл v1 переопределял штатные `preset-standard` и `preset-cordis` (patch заменяет весь config декларации), и в переписанный список плагинов была добавлена строка `tool-subagent-list-agents` с именем пакета `@deepseek-ai/dsh-tool-subagent-control/list-agents` — **такого export-субпути у пакета нет** (exports: `.`, `./src/*`, `./package.json`, `./locale/*`; все три инструмента управления регистрирует основной вход). Неразрешимый модуль → ревизия пресета не активировалась → любая сессия standard/cordis не могла собрать агента при возобновлении. Дополнительная ошибка того же класса: скопированное `!!js`-выражение `customSkillDirs`, резолвящее пакет относительно патча (из workspace-бандла не разрешается). Именно сломанная ревизия cordis объясняет и «зависание» запланированных сессий — планировщик доставлял сообщение, но агент не материализовался.

**Исправление (v2):** бандл **не переопределяет ни одну штатную строку**. Состав: 2 host-строки (`subagent` лимиты; политика моделей) + 9 аддитивных пресетов. Оркестратор — отдельный пресет `ho-orchestrator`, выбираемый при создании сессии. Ошибочная строка `list-agents` и `!!js`-резолверы удалены. Сломанная декларация пресета теперь в принципе не может затронуть чужие сессии (диагностика в ростере, сессии на штатных пресетах не зависят).

**Отдельно (не связано с бандлом):** boot-ошибка `@local/dsh-locale-ru: failed` существует с 09.11 — русификатор вызывал `addLanguage('ru')`, а в 0.2.2-rc.1 язык `ru` уже встроен. Исправлено 12.11 в самом русификаторе (addLanguage убран; встроенные namespace пропускаются).

## 1. Границы, обеспеченные технически (configuration/runtime)

| Граница | Механизм | Доказательство |
|---|---|---|
| Глубина делегирования ≤ 2 | `subagent.maxDepth=2` + `maxDepth` в инструментах; runtime-проверка каждого старта | T07: `Error: subagent depth 3 exceeds maxDepth 2` |
| Пул ≤ 6 активных субагентов | `subagent.maxActiveSubagents=6`; отказ при переполнении, без очереди | T08: 7-й запуск отклонён, «active child limit: 6» |
| Воркеры не делегируют | в пресетах уровня 2 нет делегирующего инструмента (+ runtime depth) | состав пресетов; предохранитель depth |
| Read-only роли | explorer/reviewer/auditor: `tool-fs {write,edit,applyPatch=false}` + без shell/jobs | T11 (новая сессия: NO-WRITE-TOOL-CONFIRMED) |
| Только нативные модели | политика сессии `allowedModels: zai/*`; маршруты вне политики → ошибка до создания ребёнка | отказ `zai/glm-5.3` до установки политики; T12 |
| Наследование scope/approval ребёнком | «permission scope was fixed when you were started and cannot be widened from inside» — runtime-утверждение каждому child | системный runtime-context child |

## 2. Границы advisory-only (инструкции, честно помечены)

- **Владение путями записи** — `allowed_paths` соблюдаются дисциплиной (персоны + AGENTS.md), а не блокировкой fs. Частичная техническая защита: штатный `edit` отвергает правку файла, изменившегося после чтения (`FS_STALE_VERSION`).
- **Лимит ретраев (≤2 → blocked)** и **quality gate (review до приёмки)** — инструкции; runtime не принуждает.
- **Бюджет токенов** — `NOT_ENFORCED`: штатного измеримого бюджетного механизма, который можно применить без собственного контроллера, в 0.2.2-rc.1 не задействовано; имитация hard cap запрещена ТЗ. Наблюдаемость: token-meter/session stats в UI.
- Персон/AGENTS.md — поведенческие инструкции, не sandbox-политика (прямо отмечено в AGENTS.md).

## 3. Секреты

- Значения ключей не читались, не копировались, не публиковались (`.credentials.yaml`, `ZAI_API_KEY`, OmniRoute-ключ не упоминаются значениями).
- Read-only ролям и всем персонам запрещено печатать значения секретов.
- Бэкап не содержит `credentials.yaml`.

## 4. Запрещённые операции (не выполнялись)

Деплой, миграции, production-инфраструктура, обновление Harness, удаление плагинов/данных пользователя, перезапись пользовательских настроек целиком. Существующие настройки (включая OmniRoute-провайдер `<external-gateway>`) сохранены без изменений и не используются новой конфигурацией.

## 5. Остаточные риски

1. Volatile-настройки `subagent` пользователь может поднять через UI (штатное поведение; значение из бандла — база, поверх которой работает «reset»).
2. `agentOptions` не закреплены: ребёнок наследует модель родителя; при смене корневой модели `/model` дети по умолчанию следуют за ней (в пределах политики).
3. Модель `zai/glm-5.3` включена в политику до завершения проверки каталога — если каталог её не содержит, выбор маршрута даст явную ошибку (не fallback); тогда убрать строку из бандла (см. 07-rollback).
4. Политика маршрутов применяется только к новым корневым сессиям; открытые старые сессии сохраняют прежнее ограничение «только маршрут родителя».
5. Дети наследуют approval-политику/permission корневой сессии: в сессии с `danger-full-access` технической песочницы записи нет — read-only обеспечен только составом инструментов.
6. ~~Доставка планировщика в новую сессию не запускает агент~~ — **снято 12.11**: причина была в сломанной ревизии пресета cordis (см. разбор инцидента). После v2 доставка проверяется пробой HO-PROBE-V2; результат — в `tests\evidence\new-session-report.md`.
